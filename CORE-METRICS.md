# Six core product metrics (core-v1)

The operations dashboard `/admin.html` and its CSV export include the six metrics, split into love / deep / buddy. Percentages aggregate numerators and denominators, never average mode percentages. All date selection uses Beijing time. A zero denominator is unknown/no sample, not 0%.

1. Survey completion: first-time users who submit within 7 days of their first observed answer interaction / first-time users observed for 7 days. `survey-start` is authenticated and only accepts love/deep; it stores an account ID, mode, timestamps and whether a saved questionnaire already exists. Repeated interactions deduplicate by account+mode. Saved-questionnaire edits are reported separately. Submission is recorded by the successful server-side save transaction, never by a client success claim. Incomplete observation windows are counted as waiting.
2. Coverage: recommended account-weeks / eligible account-weeks, from immutable publication snapshots. Buddy cards deduplicate by account. Snapshot insertion and matching publication share the same transaction; zero-match batches are also recorded. Previews do not count.
3. Mutual acceptance: pairs that have ever mutually accepted / published pairs. Existing persistent acceptance flags (or love connected_at) preserve acceptance after closing a conversation. Pending responses remain in the denominator and may update later. This is separate from contact exchange.
4. Two-way chat: accepted pairs with at least one message from each actual participant / accepted pairs. A pair is keyed by mode + pair ID.
5. Continued conversation: two-way chats with both participants sending on at least two distinct Beijing dates in the first 7 days after the first message / two-way chats whose first-message observation window is at least 7 days old. No message bodies are queried. Boundary is [start, start+7days).
6. Next-week participation: account-weeks also eligible in the next calendar week / account-weeks whose next week has a complete publication snapshot. No next snapshot (including a missed or unpublished batch) means waiting, not churn. Auto-participation in deep/buddy is included; this is not a return-visit metric. Pause motives are not collected or inferred.

History: questionnaire starts are not reconstructed. Publication snapshots begin at deployment. Acceptance/chat can be computed for retained published batches using existing pair flags and message timestamps. Deleting an account cascades its analytics records and can change historical totals. A small `core_metric_exclusions` table excludes designated demonstration accounts; the known chat demo is seeded by exact username. All metrics intentionally avoid questionnaire answers, message text, contact information and authentication data.

Validation: `node api/core-metrics.test.js` covers observation windows, mode isolation, denominators, exclusions and next-week boundaries. Additional MySQL fixture tests exercise all query paths, Beijing midnight, publication deduplication and survey completion idempotence. Browser tests cover desktop/mobile, empty states, CSV and first answer interactions in both questionnaire UIs.
